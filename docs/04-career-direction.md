## 一段话叙事（可放作品集 / 简历项目描述）

「我在规则密集、组合爆炸的周易命理领域自建了一套端到端数据工程流水线：多源语料采集、确定性清洗、繁简统一、文本与证据双重 QC、结构化标注与批次版本管理，产出 927 节点 / 1099 边 / 798 证据的可审计知识图谱。它的核心价值是提供了 LLM 训练所需的 ground truth：规则、置信度、条件与出处都可验证，因此可以继续产出 SFT 指令数据、偏好对、Agent 轨迹与模型评估基准。下一步计划基于该数据跑小模型 SFT / DPO / GRPO 实验，并用图谱评估器做 checkpoint 对比与遗忘检测。」

## 诚实边界

- 已可演示：数据流水线、QC 报告、MCP 工具、确定性评估、本地图浏览器
- 规划中：SFT / RL 训练实验、模型合版、分布式调优——面试与简历中明确标注「计划 / 学习中」
- 区分「做过」与「打算做」：把规划表述为经验，会在技术深挖时无法自洽，反而伤害可信度

## 建议的下一步开发顺序

1. 把图谱规则渲染成第一批 SFT 指令样本（100 条小批量验证 → 全量）
2. 用确定性评估器生成偏好对，跑通「图谱 ground truth → 偏好数据」的闭环
3. 记录 Agent 通过 MCP 完成查询任务的轨迹，产出第一批 trajectory 数据
4. 用同一批数据跑小模型 SFT，图谱评估器打分，形成第一个「数据 → 训练 → 评估」闭环
5. 再扩展 DPO / GRPO、混合比例实验与 checkpoint 对比——每一步都沿用小步验证的方法
